El mecanismo de C1 es el lock de fila dentro de la función: reemplazarla exige
**COMMIT** para que otras sesiones la vean, así que no puede mutarse "dentro de
una transacción". Se hizo de forma controlada en `tei_test`:

1. Se guardó `pg_get_functiondef(...)` original → md5
   `39e52228bad2c968d8f24f29b93d6c94`.
2. Se reemplazó la función por una versión **no atómica** (lee `ultimo` sin
   lock, escribe `leído+1`; cuerpo completo en el apéndice A) y se commiteó.
3. Se ejecutó `0021_02` → **exit 1**:
   ```text

   llegaron [1, 1, 1, 1, 1, 1, 1, 1]
   ```
   (segunda corrida: `[1, 1, 1, 1, 1, 1, 1, 2]`). El contador quedó en 0 filas
   tras la limpieza del propio test: **la prueba falla por la razón correcta y
   limpia**.
4. Se restauró la función original y se verificó el mismo md5

  O2.2. La base impone estructura/uniqueness/FKs; **no** puede obligar por

- **Cierre de sesión a 15 min, compactación de contexto, OTP**: runtime/orquestador
  (O3.x, D-12). Sin cobertura aquí.
- **Mapping HTTP** `23505/23P01→409`, `23514/23502→422`: backend, no DB.
- **Concurrencia de RLS con dos conexiones sobre las tablas nuevas**: 0021_03 es
  una sesión; el patrón está probado con dos conexiones en
  `0020_02_dos_conexiones.sh` para las tablas de 0020. No se repitió para las 8
  tablas del módulo (el mecanismo —política + FORCE + rol— es el mismo y M5

- **`nucleo.auditoria` general**: no se probó su append-only aquí (es 0004/0020;

- **Backend aún conecta como `postgres` (BYPASSRLS)**: en la base de la app el
  aislamiento de estas 8 tablas sería inerte hasta que el wiring use `tei_app`
  (criterio O7.1). Es un riesgo de despliegue, no de este esquema; se declara.

## Apéndice A — Función no atómica usada para mutar C1

Se aplicó con `supabase_admin` (COMMIT), se corrió `0021_02` (falló como se
esperaba) y se restauró la definición original. Cuerpo exacto:

```sql
create or replace function nucleo.obtener_siguiente_id_comercial_flete(
  p_empresa_id uuid, p_cliente_id uuid, p_prefijo text
) returns text language plpgsql as $function$
declare
  v_numero bigint;
begin
  if p_prefijo is null or p_prefijo !~ '^[A-Za-z0-9]{2,8}$' then
    raise exception 'Prefijo comercial inválido: % (2 a 8 caracteres alfanuméricos)',
      coalesce(p_prefijo, 'NULL') using errcode = '23514';
  end if;
  if not exists (
    select 1 from nucleo.clientes c
     where c.id = p_cliente_id and c.empresa_id = p_empresa_id
  ) then
    raise exception 'El cliente % no pertenece a la empresa % (la secuencia es por empresa-cliente)',
      p_cliente_id, p_empresa_id using errcode = '23514';
  end if;

  -- NO atómico: lee sin bloquear y luego escribe el valor leído + 1
  select coalesce(ultimo, 0) + 1 into v_numero
    from nucleo.id_comercial_contador
   where empresa_id = p_empresa_id and cliente_id = p_cliente_id;
  if v_numero is null then v_numero := 1; end if;

  insert into nucleo.id_comercial_contador (empresa_id, cliente_id, ultimo)
    values (p_empresa_id, p_cliente_id, v_numero)
    on conflict (empresa_id, cliente_id)
    do update set ultimo = excluded.ultimo;

  return upper(p_prefijo) || '-' || lpad(v_numero::text, 5, '0');
end;
$function$;
```

Restauración verificada con
`md5(pg_get_functiondef('nucleo.obtener_siguiente_id_comercial_flete(uuid,uuid,text)'::regprocedure))`
= `39e52228bad2c968d8f24f29b93d6c94` antes y después.
